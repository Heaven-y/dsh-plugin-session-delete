# @coder02lq/dsh-plugin-session-delete

**给 DeepSeek Harness 补上「删除会话」：侧边栏 `⋯` 菜单里的一个删除项，二次确认，真正从磁盘上清干净。**

DSH 出于设计只提供归档，不提供删除——会话能隐藏，但日志会永远堆在磁盘上。
这个插件把删除能力补回来，作为一个可随时卸载的 bundle，不改官方任何代码。

```
订阅会话 ⋯  →  删除会话  →  确认  →  日志、投影缓存、工作区登记一并清除
```

## 功能

- **侧边栏菜单项**：会话行的 `⋯` 菜单新增「删除会话」，排在「归档会话」与「会话 ID」之后，带分隔线，用危险色标注。
- **二次确认弹窗**：删之前告诉你到底会删掉什么，并说明子代理会话会被连带删除；Esc、点击遮罩均可取消，焦点会归还到触发按钮。
- **子代理级联**：连同该会话的全部子代理子孙一起删除。子代理会话在侧边栏是被隐藏的，且打开它必须经由父会话，父会话一删就再也无法访问——所以留着只是占磁盘的孤儿。**fork 出来的会话不受影响**，它们有自己独立的侧边栏行和生命周期。
- **彻底清理**：对话日志、投影缓存、工作区登记、归档/置顶集合，一处不留。
- **诚实失败**：文件删不掉时不会假装成功，会明确告诉你「登记已移除但文件还在」，让你重试或手动清理。
- **Agent 工具**：同时暴露 `session_delete` 工具，附带「不得删除自己所在会话」的护栏。

## 安装

### 桌面端（DeepSeek Harness App）

**设置 → 插件 → 添加插件**，输入包名：

```
@coder02lq/dsh-plugin-session-delete
```

装完**完全退出并重开 App**，侧边栏会话的 `⋯` 菜单里就会出现「删除会话」。

> ⚠️ 桌面端的 profile 不能用 CLI 安装（DSH 对 `desktop` profile 做了排他保护），请走上面的「设置 → 插件」。

### Web / CLI profile

```sh
dsh plugin --profile <profile> add @coder02lq/dsh-plugin-session-delete
```

装完重启该 profile。

也可以直接从 GitHub 装（会锁定到具体 commit）：

```sh
dsh plugin --profile <profile> add github:coder02lq/dsh-plugin-session-delete
```

## 一次删除到底做了什么

| # | 步骤 | 为什么 |
|---|---|---|
| 1 | 归档并停止该会话的工作 | 先写归档集合再派发停止，停止过程唤醒的任务因此已被拦截 |
| 2 | 等待会话真正退出（≤15 秒） | 运行中的会话持有写租约和内核锁，其收尾还会重写投影缓存；在它活着时删除会两边都破坏 |
| 3 | 从工作区行、归档集合、置顶集合摘除 id | 三处独立持有这个 id |
| 4 | 删除投影缓存行 | 派生数据，必须等第 2 步之后，否则会被写回来 |
| 5 | 删除会话目录 | 当前日志代、历史日志代、POSIX 租约文件在同一目录；附件是内容寻址共享的，不动 |
| 6 | 重建内存中的 header 索引 | 不做的话进程会一直「记得」这个已删会话，直到重启 |

侧边栏会自动刷新：注册表写入会发 `domain/changed`，工作区 feed 转成 `upsert`/`archived` 帧，客户端本来就在订阅。

**子代理级联**发生在第 1 步之前：先读出整棵子代理血缘（父在子前），删完父会话后再逐个清理，已消失的子会话会被跳过而不是报错。

## 换台电脑、换个系统

**跨操作系统可用。** 代码里没有平台分支，不读 `process.platform`，不拼盘符或路径分隔符，只用 `node:fs/promises` 和 `node:path`。会话文件在哪是问持久化层的（`locate(header)`），所以 Windows 的 `C:\Users\…\.dsh\sessions\…` 和 macOS 的 `~/.dsh/sessions/…` 都不需要插件知道区别。

唯一的系统差异是**删除被占用的文件**：Windows 会让 unlink 失败，macOS 会「成功」但持有者能重建路径把会话复活。所以这里先等宿主写入方退出，再短暂重试，最后如实报 `session/locked`。

**跨 DSH 版本不保证。** 插件必须碰一些非公开的内部接口（`replaceHeaderIndex`、`session_projcache` 表、`locate`）。风险最高的两处做了防御式解析，但 Workspace 注册表若改变形状就需要更新代码。

## 已验证 / 未验证

**已验证：**
- Host 侧 9 项测试：六步顺序、已归档会话不重复归档、运行中会话会等待、拒绝操作零副作用、日志已丢但仍有登记的 id 会被清理、删不掉的目录报 `session/locked`、**级联两层级联且 fork 存活**、工具拒绝删除自身会话。
- Client 侧 7 项测试：工厂导出、挂载的 descriptor 与 Host 签名一致、两个 slot 注册、中英词典、样式仅用主题 token、失败信息透传、缺少 namespace 时报可读错误。
- 真机：创建一次性会话后通过 `session_delete` 成功删除，日志目录、投影缓存、工作区引用三处均干净。

**未验证：** 弹窗与菜单项的**实际渲染效果**未在浏览器中目视确认（开发环境没有浏览器控制权，页面需要浏览器自身的会话令牌）。标记与样式照搬宿主自己的 `Modal`/`MenuItemButton`/`Button` 实现，理论上一致，但属于推断而非观察。浅色/深色主题下的视觉效果仍待确认。
